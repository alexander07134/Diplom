# Отчёт о результатах автоматизации тестирования (Result.md)

## 1. Общая информация
* **Объект тестирования:** Мобильное приложение «Мобильный хоспис» (Android).
* **Цель:** Автоматизация UI-тестов с использованием фреймворка Espresso и формирование отчётов Allure.
* **Инструменты:** Java, Espresso, JUnit 4, Allure, Android Studio, эмулятор Pixel 6 (API 36).

## 2. Сравнение ручного и автоматизированного тестирования

| Параметр | Ручное тестирование | Автоматизированное тестирование |
| :--- | :--- | :--- |
| **Затраченное время** | ~8 часов (написание чек-листов и ручной прогон) | ~10 часов (написание тестов, отладка, настройка CI) |
| **Время повторного прогона** | 2-3 часа | ~1 минута (запуск через Gradle/Android Studio) |
| **Покрытие функционала** | 100% (51 тест-кейс) | ~55% (28 автотестов) |
| **Стабильность** | Высокая (человек видит всплывающие окна) | Средняя (есть проблемы с перехватом системных окон) |

## 3. Результаты прогона тестов (Статистика Allure)
Всего запущено: **28 тестов**.
* ✅ **17 тестов прошли успешно** (зелёные).
* ⚠️ **11 тестов упали** (жёлтые).

### 3.1. Успешно пройденные тесты (17)
* **AuthTests (4):** Успешная авторизация, логин с пробелами (в начале и в конце), проверка маскировки пароля.
* **NavigationTests (5):** Проверка отображения главного меню, кнопки ALL NEWS, переключение между Main и News, свёртывание/разворачивание приложения, закрытие через "Назад".
* **NewsTests (6):** Создание новости, удаление новости, редактирование заголовка, редактирование описания, просмотр списка новостей, создание новости с датой в будущем (баг зафиксирован).
* **QuotesTests (2):** Просмотр раздела цитат, отображение текста цитат.

### 3.2. Упавшие тесты (11) и причины падения
Все падения связаны с **негативными сценариями** (проверка валидации).

| Группа | Тесты | Причина падения |
| :--- | :--- | :--- |
| **AuthTests** | `testEmptyFields`, `testEmptyLogin`, `testEmptyPassword`, `testInvalidLogin`, `testInvalidPassword`, `testLoginUppercase`, `testLoginMixedCase`, `testLoginSpecialChars` | `NoMatchingViewException`. Тесты не могут найти текст ошибки (Snackbar). |
| **NewsTests** | `testCreateNewsEmptyFields`, `testCreateNewsWithoutDescription`, `testCreateNewsWithoutTitle` | `NoMatchingViewException`. Тесты не могут найти текст ошибки «Fill empty fields». |

**Детальный разбор причины:**
Всплывающие сообщения об ошибках (Snackbar) в Android реализованы как **отдельные системные окна (PopupWindow)**, а не как часть основного layout-файла экрана. Стандартные методы Espresso (например, `onView(withText(...))`) ищут элементы только в основном дереве View текущей активности. Из-за этого автотест «не видит» Snackbar и падает с ошибкой `NoMatchingViewException`.


## 4. Найденные баги (Issues)

В ходе ручного и автоматизированного тестирования были выявлены следующие дефекты:

| ID | Описание | Серьёзность | Статус |
| :--- | :--- | :--- | :--- |
| **BUG-01** | **Создание новости с датой в будущем.** При создании новости с датой, превышающей текущую (например, 01.01.2030), приложение позволяет сохранить новость. Ожидается: валидация с ошибкой «Дата не может быть в будущем». | Medium | Открыт |
| **BUG-02** | **Нестабильные ID элементов карточки новости.** В RecyclerView элементы внутри карточки (кнопки удаления/редактирования) не имеют постоянных уникальных ID (используются общие ID для всех карточек). Это затрудняет автоматизацию работы с конкретной новостью. | Low | Открыт |

## 5. Почему не все 51 тест-кейс автоматизированы

В документации (`Cases.xlsx`) описано 51 тест-кейс. В автоматизацию перенесено 28. Остальные **23 тест-кейса не были автоматизированы** по следующим объективным причинам:

1. **Визуальные проверки (6 тестов):** Например, «шрифты читаемы», «цветовая гамма не напрягает глаза», «интерфейс адаптируется под экран». Espresso не умеет оценивать визуальную эстетику или рендеринг шрифтов.
2. **Проверки с участием внешних систем (3 теста):** Например, «Поделиться цитатой» (открывается системное меню Android, выбор WhatsApp/Telegram и т.д.). Espresso работает только в рамках тестируемого приложения и не может взаимодействовать с системным UI.
3. **Нестабильные элементы и зависимость от внешних данных (5 тестов):** Например, «Фильтрация по категории». Если на сервере нет новостей нужной категории, тест упадет (ложное падение). Также копирование текста в буфер обмена (TC-32) работает нестабильно в рамках UI-тестов.
4. **Граничные значения без четких требований (4 теста):** Например, «Создание с очень длинным заголовком» (TC-23). Без доступа к исходному коду непонятно, должна ли программа обрезать текст, выдавать ошибку или пропускать его.
5. **Сложные сценарии взаимодействия с сетью (5 тестов):** Например, «Пагинация», «Потеря интернета». Проверка этих кейсов требует управления сетевым состоянием эмулятора через ADB, что выходит за рамки UI-автотестов и приводит к нестабильности.

## 7. Выводы
Автоматизация позволила покрыть основной позитивный функционал приложения (CRUD новостей, авторизация, навигация) и зафиксировать известные баги. Основная проблема, с которой пришлось столкнуться — это перехват системных всплывающих окон (Snackbar) в негативных тестах, что требует внедрения специальных матчеров в будущем.
